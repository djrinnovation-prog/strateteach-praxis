● סודי · לעיני הבעלים בלבד

Phase 1 — שירות‑הביצוע המבודד · מפרט טכני

(Isolated Execution Service · Technical Spec) · טיוטה לאישור בעלים + אורן

תאריך: 2026‑07‑16 בעלים: דן · רפי · יואב מפעיל‑ביצוע: אורן (תפקיד מתוחם) סטטוס: טיוטה — לפני קוד
נלווה לדף‑ההחלטה. כל מה שכאן נבנה DISARMED · testnet בלבד · אפס כסף‑אמיתי. המסמך לא מבצע כלום.

0עקרונות‑בטיחות (מוטבעים בקוד, לא אופציונליים)

  1. גייט‑ראשי EXECUTION_ARMED=false — ברירת‑מחדל כבוי. שום הזמנה לא יוצאת כשהוא כבוי. הדלקה = פעולת‑בעלים מפורשת, לא שלי.
  2. ENVIRONMENT=testnet עד go‑live מפורש. mainnet חסום בקוד (env‑guard) — חשבון‑testnet לעולם לא נוגע ב‑credential של mainnet.
  3. הפרונט לא מחזיק מפתחות. מפתחות‑בורסה חיים רק בכספת צד‑שרת. אני (הסוכן) לא רואה, לא מזין, ולא נוגע במפתחות בשום שלב.
  4. Envelope‑only: הסיגנל נושא כוונה בלבד — לא כמות, לא סימבול חופשי, לא מפתח. הכמות מחושבת בצד‑שרת מה‑config.
  5. הון‑בעלים = 3‑מ‑3. כל arming/ביצוע על הקרן המשותפת דורש 3 אישורים מפורשים. אין ביצוע אוטונומי על כסף‑אמיתי.
  6. Kill‑switch + audit + reconciliation מהיום הראשון. כל פעולה נכתבת ל‑audit בלתי‑הפיך.
  7. הפרדה מוחלטת מכספי‑לקוחות ומ‑AutoPilots‑הדמו.

1ארכיטקטורה (רכיבים)

StrateTeach (סורק / UI / advisory)                    שירות‑הביצוע (מבודד, בבעלות החברה)
        │  כוונת‑מסחר (signal)                                │
        └──►  Signal Ingress  ──HMAC──►  Queue  ──►  Worker  ──►  Vault(keys)  ──►  Exchange (ccxt, testnet)
                    │                       │           │                              │
                 dedup/                  durable     sizing/caps                     fills →
                 freshness              (no loss)    kill‑switch                   reconciliation
                    └──────────────────────────── audit_log (append‑only) ──────────────────────┘
  • Signal Ingress — מקבל כוונת‑מסחר חתומה (HMAC). מאמת חתימה, dedup, freshness, rate‑limit. לא מבצע — רק מכניס לתור.
  • Queue — עמיד (durable), בלי איבוד שקט. סמן‑התאוששות (sweeper) על כשל.
  • Worker — תהליך נפרד. מושך מהתור, מחשב כמות (config), אוכף caps + גייט + env, שולף מפתח מהכספת, שולח הזמנה, כותב תוצאה + audit.
  • Vault — כספת צד‑שרת למפתחות. הבעלים מזינים; ה‑worker בלבד קורא; שום מקום אחר.
  • Audit / Reconciliation — כל אירוע נכתב; התאמה מול הבורסה (requested↔executed) לתפיסת סטיות.

3חוזה‑הסיגנל (Signed Signal Contract)

  • תחבורה: POST חתום HMAC‑SHA256 (מפתח‑חתימה צד‑שרת, מתחלף, לא ב‑UI).
  • מטען (envelope‑only): signal_id (חובה, ממקור), action (buy/sell), אופציונלי fire_time/freshness.
  • אסור במטען: מפתחות, כמות, חשבון, סימבול‑חופשי. הכמות והסימבול נקבעים בצד‑שרת מה‑exec_bots.
  • תגובה: אחידה (200 לכל תוצאה עסקית, בלי דליפת‑מבנה). כשל‑תשתית = 5xx לפני הכתיבה (retry).
  • הגנות: dedup (signal_id), חלון‑freshness, rate‑limit לכל בוט.

4גייט + סיכון + kill‑switch

  • גייט‑ראשי: EXECUTION_ARMED (כבוי). כבוי → כל ביצוע no‑op עם audit.
  • Env‑guard: testnet → אסור לגעת ב‑credential של mainnet.
  • Caps (צד‑שרת, fail‑closed): per‑order notional, daily notional, מקסימום פוזיציות. חריגה = דחייה + audit.
  • Kill‑switch: בכפתור אחד — trading_enabled=false לכל הבוטים + השהיית‑תור. מבוקר, כותב audit, לא מזיין‑מחדש לבד.

5מסלול הון‑הבעלים (הקרן המשותפת · 3‑מ‑3)

בקשת‑פעולה (owner) → 3 אישורים מפורשים → חלון‑זמן → ביצוע דרך ה‑worker → audit + reconciliation
  • קרן אחת משותפת; ledger הפקדות → אחוז‑בעלות → NAV; לכל בעל חלקו היחסי.
  • בלי 3 אישורים — שום דבר לא זז. האישור נכתב ל‑owner_approvals + audit_log.
  • מנותק לחלוטין מכספי‑לקוחות.

6מפתחות / כספת

  • מפתחות‑בורסה: הבעלים מזינים ישירות לכספת צד‑שרת (לא דרכי, לא דרך ה‑UI‑הישן). ה‑worker בלבד קורא בזמן‑ביצוע.
  • החלטה פתוחה (§10): בחירת הכספת — Vault / cloud‑KMS / הצפנה‑ברמת‑אפליקציה עם מפתח‑KMS. (המלצה: כספת ייעודית עם הפרדת‑הרשאות.)

7תפקיד אורן — "מפעיל‑ביצוע" (מתוחם)

  • יכול: לנטר (dashboard/status), להגדיר בוטים (pair/caps בתוך המדיניות), להפעיל kill‑switch, לנהל את הפרויקט הזה.
  • רואה את כל המבנה הפיננסי של המערכת: כספי‑חברה, מישור‑הביצוע כולו (exec_bots, exec_orders, exec_signals, exec_state, caps, reconciliation), תזרימי‑כסף ודוחות מבניים. הוא מנהל את המכונה הפיננסית.
  • לא רואה — owner‑only: owner_fund ו‑owner_approvals — הקרן המשותפת, השקעות‑הבעלים וכל תנועותיהן (הפקדות, משיכות, מסחר על הון‑הבעלים, חלוקה/NAV, אישורי ה‑3‑מ‑3). ההון הפרטי של הבעלים ותנועותיו חסומים ממנו ברמת‑ההרשאות.
  • לא יכול: בעלות‑IP, החזקת‑מפתחות מחוץ למערכת, arming על הון‑בעלים בלי 3‑מ‑3, שינוי governance.
  • הכול בתוך מערכת‑האם, עם audit לכל פעולה.

8תוכנית testnet (שערי‑אימות לפני mainnet)

  1. Smoke: הזמנת‑testnet אחת, exactly‑once, caps מכובדים, disarm מיד.
  2. קמפיין: N מילויים, dedup/freshness/rate‑limit, reconciliation ירוק.
  3. Kill‑switch drill + rollback drill.
  4. רק אז — שער go‑live נפרד (Phase 5), אישור‑בעלים בכתב + provenance/רישוי סגור.

10פתוח / דורש החלטה

  1. מיקום: שירות נפרד (repo/deploy משלו) — מומלץ — או מודול מבודד בתוך ה‑backend הקיים לתחילת‑דרך.
  2. כספת: Vault / KMS / app‑encryption. (בעלים/אורן.)
  3. תור: pgmq (Postgres) או תור‑Python. (המלצה: pgmq — עמיד, פשוט.)
  4. סורק‑הסיגנלים: StrateTeach שולח כוונות דרך ה‑Ingress החתום (server‑side token).
טיוטה. לא מבצעת פעולה, לא מזיזה כסף, לא מדליקה mainnet. כל arming/go‑live/הזנת‑מפתחות = פעולת‑בעלים מפורשת, תחת 3‑מ‑3 להון‑בעלים.
